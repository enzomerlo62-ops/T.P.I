DECISIONES TÉCNICAS
-------------------
[10/11] [L] DECISIÓN: contador de id compartido por todas las entidades (en Base) → ids únicos en todo el sistema, más simple de implementar
[10/11] [L] DECISIÓN: Pedido.agregar_detalle verifica el stock pero NO lo descuenta; lo descuenta PedidoServicio al confirmar el pedido completo → si falla un detalle, no queda stock modificado a medias
[10/11] [L] DECISIÓN: al agregar un producto repetido se compara la cantidad ACUMULADA contra el stock → evita superar el stock en dos pasos
[10/11] [L] DECISIÓN: la contraseña no tiene property, solo verificar_contrasenia() → la contraseña nunca sale del objeto
[10/11] [L] DECISIÓN: Pedido.detalles devuelve una tupla → la lista no se puede modificar desde afuera
[10/11] [L] DECISIÓN: se definió __eq__ y __hash__ en Base comparando por id → una sola vez para todas las entidades
[10/11] [L] DECISIÓN: el detalle guarda el precio unitario al momento de agregarse → el subtotal no cambia si después cambia el precio del producto


DIFICULTADES Y SOLUCIONES
-------------------------
[10/11] [L] DIFICULTAD: ModuleNotFoundError al importar Pedido → el archivo se llamaba forma_de_pago.py y el import decía forma_pago; se renombró el archivo
[10/11] [L] DIFICULTAD: Base se podía instanciar aunque heredaba de ABC → hace falta al menos un @abstractmethod; se declaró __str__ abstracto
[10/11] [L] DIFICULTAD: los objetos daban "unhashable type" → al definir __eq__ Python anula __hash__; se agregó __hash__ por id
[10/11] [L] DIFICULTAD: el subtotal cambiaba al cambiar el precio del producto → se guarda el precio unitario en DetallePedido
